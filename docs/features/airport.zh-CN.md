# 机场订阅管理

SublinkPro 提供了完善的机场订阅管理功能，不仅能将订阅转换为节点，还能全方位监控和管理您的机场服务。

---

## 💡 核心功能

| 功能 | 说明 |
|:---|:---|
| **📥 多格式导入** | 支持 Clash/mihomo、V2Ray 订阅格式的自动解析与导入；Mieru 与 Snell 仅支持 Clash/mihomo YAML |
| **⏱️ 智能定时更新** | 内置 Crontab 级调度器，支持按时间间隔或 Cron 表达式自动更新订阅，确保节点时刻在线 |
| **📊 流量用量监控** | 自动解析订阅返回的 `Subscription-Userinfo` 头，直观展示**已用上传**、**已用下载**、**总流量**及**过期时间**，并提供机场维度的流量历史图表 |
| **🚀 立即更新机制** | 支持一键「立即拉取」，配合实时回调机制，无需刷新页面即可看到最新的流量数据和节点列表 |
| **⚡ 更新后检测** | 机场可绑定节点检测策略，订阅更新成功后立即针对该机场节点执行检测 |
| **🤖 Bot 集成管理** | 通过 Telegram Bot 可随时查询各订阅的剩余流量、到期时间，并支持远程触发更新任务 |

### Clash / mihomo `proxy-providers` 兼容说明

- 机场订阅导入支持 Clash / mihomo YAML 中的 `proxy-providers`，当顶层没有 `proxies` 但 provider 中包含节点时，也会展开并导入为普通节点。
- 当前会远程拉取 `type: http` 的 provider，并复用机场订阅本身的代理下载和忽略 TLS 证书验证等行为；provider 请求始终携带 User-Agent，只有 provider URL 与根订阅 URL 同 host 时才会继承自定义 Header，跨 host provider 和跨 host 跳转不会携带自定义 Header。
- 系统优先展开 `proxy-groups[].use` 引用到的 provider；当分组启用 `include-all` / `include-all-providers`，或配置中没有任何分组引用时，会按配置声明顺序展开所有 HTTP provider。
- Provider 响应支持标准 YAML 顶层 `proxies`；如果 provider 返回的是 base64 或明文 URI 行列表，也会按普通订阅链接兼容解析。
- 当前不会实现本地 `file` provider、provider 缓存、定时健康检查、完整 mihomo override 语义或 provider 自身的 `proxy` 路由；这些运行时能力仍应由 Clash / mihomo 客户端处理。

### VLESS / XHTTP 兼容说明

- 机场订阅导入现已支持 `vless://` 链接中的 `type=xhttp`。
- 当上游订阅是 Clash / mihomo YAML 且节点为 `type: vless`、`network: xhttp` 时，系统会识别 `xhttp-opts` 并回写为 VLESS URL。
- 当前已支持的 URL 顶层字段包括：`type`、`encryption`、`path`、`host`、`mode`、`extra`、`ech`。
- `extra` 中已支持映射到 mihomo 的字段包括：`headers`、`noGRPCHeader`、`xPaddingBytes`、`downloadSettings` 及其已知子字段。
- 顶层 `ech` 会优先映射到 mihomo 顶层 `ech-opts`：当值是固定 base64 ECHConfig 时写入 `config`，当值是 Xray 的 DNS / URI 风格时会按 mihomo 可表达的范围做最佳努力映射。
- 当机场订阅本身是 Clash/mihomo YAML，且导入时只能从顶层 `ech-opts` 恢复出 `query-server-name` 时，系统会在保存节点链接前按本地兼容规则重建为 `ech=<query-server-name>+https://dns.alidns.com/dns-query`。
- `extra.downloadSettings.echOpts` 仍只映射到 mihomo `xhttp-opts.download-settings.ech-opts`，不会和顶层 `ech-opts` 混写。
- `xmux`、`sessionPlacement` 等在 Xray 侧存在但 mihomo 当前没有公开承载字段的扩展项，会被视为未支持，不会静默降级成 `http`、`h2` 或 `grpc`。

### Mieru 兼容说明

- 机场订阅导入支持 Clash/mihomo YAML 中的 `type: mieru` 节点，并保留 mihomo 官方字段：`server`、`port` 或 `port-range`、`transport`、`username`、`password`、`multiplexing`、`traffic-pattern`。
- Mieru 官方存在 `mieru://` / `mierus://` 分享链接，但未定义适合 SublinkPro 原始编辑器逐字段修改的通用 URL schema。系统保存节点时使用内部可编辑形态 `mieru://username:password@server:port?...#name`，端口范围使用 `portRange=2090-2099`，用于 Clash/mihomo YAML 导入后的回写与后续导出。
- Mieru 不会输出到 v2ray 或 Surge；这些客户端当前不在 SublinkPro 的 Mieru 支持范围内。

### OpenVPN 兼容说明

- 机场订阅导入支持 Clash/mihomo YAML 中的 `type: openvpn` 节点，并保留 Mihomo OpenVPN 字段，包括传输、加密与认证、证书和私钥块、TLS 静态密钥、账号凭据、保活、IP 栈、DNS 及通用连接层选项。
- SublinkPro 会把节点保存为内部往返链接 `openvpn://server:port?...#name`。这不是 OpenVPN 官方分享链接格式，也不包含直接导入 `.ovpn` 文件的能力。
- OpenVPN 仅输出到 Clash/mihomo；v2ray 与 Surge 输出会跳过该协议。证书和私钥内容在内部链接中仅经过 URL 编码，并未加密。

### Snell 兼容说明

- 机场订阅导入支持 Clash/mihomo YAML 中的 `type: snell` 节点，并保留 mihomo 官方字段：`server`、`port`、`psk`、`version`、`udp`、`obfs-opts`（`mode`、`host`）以及通用连接层选项 `tfo`、`mptcp`、`interface-name`、`routing-mark`、`ip-version`。
- Snell 没有官方分享链接方案。系统保存节点时使用内部可编辑形态 `snell://server:port?psk=...&version=...&obfs=...&obfs-host=...#name`，用于 Clash/mihomo YAML 导入后的回写、Surge 输出与后续导出。
- Snell 仅输出到 Clash/mihomo 与 Surge；v2ray 当前不在 SublinkPro 的 Snell 支持范围内。

## 使用流程

### 添加机场订阅

1. 进入「机场管理」页面
2. 点击「添加机场」
3. 填写订阅链接和名称
4. 按需配置请求设置（如 User-Agent、自定义 Header、代理下载）
5. 配置更新策略（可选）；如需订阅更新后立刻检测节点，可在高级选项开启「更新后检测」并选择节点检测策略
6. 保存并拉取节点

开启「更新后检测」后，只有当前机场订阅更新成功时才会触发检测；检测范围限定为该机场本次更新后的节点，不会等待节点检测策略自身的定时时间，也不会扩大到其它机场节点。如果同时开启「只检测变化的节点和新节点」，SublinkPro 只会检测本次拉取中新增或更新的节点；当本次没有新增或更新节点时，会跳过更新后检测，不会回退为检测该机场全部节点。由该功能触发的节点检测任务会在任务中心标记为「机场更新」，以便和「手动」「定时」触发区分。

### 节点处理：过滤和重命名规则

在机场编辑弹窗的「节点处理（拉取时生效）」中，可以配置：

- **节点名称过滤**：通过白名单和黑名单规则按节点名称过滤（文本匹配或正则表达式）。
- **协议过滤**：通过白名单和黑名单按协议类型过滤节点（ss、vmess、trojan 等）。
- **节点名称预处理**：重命名规则，用于转换节点名称（文本替换或正则表达式）。
- **去重规则**：自定义去重逻辑，在同一机场内去除重复节点。

**全局节点处理规则**：除了机场特定规则外，还可以在「应用设置 → 全局节点处理」中配置全局规则。全局规则应用于所有机场，并与机场特定规则叠加生效：

- **规则应用顺序**：全局过滤 → 机场过滤 → 去重 → 全局重命名 → 机场重命名 → 名称唯一化
- **过滤规则叠加**：全局和机场的黑名单/白名单会合并。
- **重命名规则叠加**：先应用全局重命名规则，再应用机场重命名规则。

说明：

- 所有节点处理规则都在**拉取订阅时生效**，修改后需要重新拉取该机场才能应用到已存在节点。
- 被过滤的节点不会存储到数据库。
- 可以从机场管理页面工具栏的「全局规则」按钮快速访问全局规则设置。

### 节点处理：名称唯一化

在机场编辑弹窗的「节点处理（拉取时生效）」中，可使用”节点名称唯一化”相关配置：

- **节点名称唯一化**：为当前机场导入的节点统一添加稳定前缀，用于避免不同机场之间出现重名节点。
- **机场内节点名称唯一化**：在同一机场内如果存在重名节点，会在当前节点名称后依次追加 `-1`、`-2`、`-3` 等数字编号。

说明：

- 两个开关都在**拉取订阅时生效**，修改后需要重新拉取该机场才能应用到已存在节点。
- 机场间前缀唯一化与机场内顺序编号可以同时开启；此时系统会先生成机场前缀，再对同机场内的重名节点追加 `-1`、`-2`… 数字编号。
- 机场内顺序编号也可以单独开启；单独开启时不会添加机场前缀，只会在同机场的重名节点后追加数字编号。
- 编号是**按重名组分别计算**的，不是全机场共享一套连续序号；例如 `HK` 重名组会得到 `HK-1`、`HK-2`，而 `US` 重名组会单独从 `US-1` 开始。

### 节点处理：国家自动预先填充与回填

机场高级选项里有两个国家填充开关。它们会使用「应用设置 -> 国家规则」中配置的规则，从上游节点名称里的国家关键词、城市名、国家代码或国旗 Emoji 解析国家信息，然后把匹配到的国家代码写入节点。

- **新节点自动填充国家**：机场拉取时，对本次新导入且国家字段为空的节点执行匹配。如果节点名称命中某条已启用国家规则，就写入该规则的国家代码，例如 `HK`、`US`、`JP`。
- **回填现存节点国家**：机场拉取时，对同一机场下所有已经存在、但国家字段仍为空的节点，都会使用本次上游节点名称执行匹配，包括本次原本不需要更新名称、链接或顺序的节点。适合在已有节点后才启用国家规则或补充规则的场景。开启该选项也会同时开启「新节点自动填充国家」。

国家填充是基于节点名称的规则匹配，不是落地 IP 检测。它不会拨号节点、不会检测出口 IP，也不会覆盖已经存在的国家代码。如果没有任何已启用国家规则命中节点名称，国家字段会保持为空。

建议使用方式：

1. 先进入「应用设置 -> 国家规则」，确认默认规则能覆盖你的机场节点命名；如果机场使用自定义命名，可新增或调整正则表达式。
2. 对希望后续新节点自动带国家代码的机场，开启「新节点自动填充国家」。
3. 如果同一机场已经有旧节点但缺少国家代码，开启「回填现存节点国家」，Web 界面会同时打开新节点自动填充，然后重新拉取一次机场；如果只是一次性补齐，回填完成后可以再关闭回填。

示例：如果 `HK` 国家规则能匹配 `香港`、`HK`、`Hong Kong` 或香港国旗 Emoji，那么 `香港 01`、`HK Premium 01` 这类节点在机场拉取时会写入国家代码 `HK`。

### 节点名称与备注

机场拉取到的节点会同时保存两个名称：

- **原始名称**：来自机场订阅链接本身，机场更新时会随上游变化刷新。
- **备注名称**：用户在节点编辑弹窗中维护的自定义名称，机场更新不会覆盖该字段；全局节点备注不能重复。

在「节点管理」编辑节点时，可以通过「实际使用名称」选择订阅输出、节点重命名规则、链式代理和节点脚本使用哪个名称：

- **使用原始名称**：按机场订阅中的原始名称操作，适合希望完全跟随上游命名的节点。
- **使用备注名称**：按用户备注作为实际节点名称操作，适合自定义命名并希望机场更新后继续保留的节点。

切回「使用原始名称」即可恢复使用机场订阅里的名称；备注名称会保留，后续可随时再次切换回来。

说明：手动编辑备注时，如果与其他节点备注重复会被拒绝；机场自动导入产生重复备注时，系统优先生成 `原始名称@机场名称`，如果仍重复则继续追加编号，例如 `香港 01@机场B-2`。没有机场来源的自动导入会使用普通编号以保持全局唯一。

### 请求设置

机场的「请求设置」支持配置拉取订阅时附带的请求参数：

- `User-Agent`：使用专用输入框设置常见客户端 UA 或手动输入。
- **设备伪装**：按设备档位（`Android`、`iOS`、`Windows`、`macOS`、`Linux`）伪装请求来源。系统会发送 `X-Device-OS`、`X-Ver-OS`、`X-Device-Model`、`X-App-Name`，未单独设置 User-Agent 时使用档位自带的客户端 UA。适合根据设备类型区分响应的面板。选择 **自定义** 后可手动填写系统名称、系统版本、设备型号与应用名称。选择预置档位时会用档位值填好同样的字段，所有字段都可以自由修改：保存什么就发送什么，清空某项即表示不发送该请求头（不会在请求时再用预置值补回）。User-Agent 取自上方的 User-Agent 字段。
- **X-HWID**：默认开启。新建机场时会预填一个随机的 32 位设备标识，并随每次订阅与用量请求发送 `X-HWID`。对把订阅绑定到设备的面板（例如 Remnawave 系面板），这样每次拉取都会被识别为同一台设备，而不会重复创建设备。可点击 **重新生成** 换一个新值，或关闭开关停止发送该请求头。
- **自定义 Header**：可按 `Header 名称` + `Header 值` 的方式添加多条请求头，适合需要额外鉴权或来源标识的机场。
- `使用代理下载`：通过指定节点或自动选择最佳节点拉取订阅。

说明：

- 自定义 Header 会在请求机场订阅地址时一并附带。
- 如果开启了「获取用量信息」，系统在刷新机场用量时也会复用相同的自定义 Header。
- `User-Agent` 使用单独字段管理，自定义 Header 中不支持再次填写 `User-Agent`。
- 自定义 Header 优先于自动生成的设备头与 `X-HWID`：例如手动添加 `X-HWID` 后，系统不再发送自动生成的值，请求头名称比较不区分大小写。
- 该功能上线前创建的机场会在启动时按机场 ID 派生并回填一个稳定值（迁移 `0040_backfill_airport_hwid`），因此编辑弹窗始终有值，上游面板也始终看到同一台设备。需要更换时使用 **重新生成** 或直接编辑该字段。
- 编辑机场不会自动替换已保存的 `X-HWID`：只有点击 **重新生成**、手动修改字段，或为没有存储值的机场开启开关时才会产生新值。

### 配置定时更新

支持两种定时更新方式：

| 方式 | 说明 |
|:---|:---|
| **按间隔更新** | 设置固定时间间隔，如每 6 小时更新一次 |
| **Cron 表达式** | 灵活的 Cron 表达式配置，如 `0 */6 * * *` |

### 流量监控

系统自动解析订阅响应头中的 `Subscription-Userinfo`，提取以下信息：
- `upload`：已用上传流量
- `download`：已用下载流量
- `total`：总流量额度
- `expire`：到期时间戳

所有机场默认开启用量获取（包括通过迁移升级的既有机场），仍可在单个机场中关闭。机场列表会显示已用流量和订阅剩余时间。当 `total` 为 `0`（不限流量）时仅显示已用流量，不显示进度条；已过期订阅会高亮提示。

### 流量历史图表

每次机场刷新成功后，系统都会在 `airport_usage_snapshots` 表中记录一条流量快照。快照用于生成机场列表中的迷你图和可缩放的用量历史弹窗。

- **列表迷你图**：开启用量获取的机场会在机场表格、列表视图和移动端卡片的用量区域显示迷你折线图。
- **用量历史弹窗**：点击图表按钮或迷你图即可打开完整图表。可选择时间范围预设（1、3、7、30、90 天或全部保留数据），切换自动（按刷新逐点）/ 按小时 / 按天粒度，并使用鼠标滚轮或底部滑块缩放；点击重置按钮可恢复完整范围。按小时 / 按天视图会把每个小时或自然日合并为一个点，取该时段最后一次成功刷新的数值。
- **刷新标记**：每次成功刷新都以蓝点标在曲线上，失败刷新以红点标出，刷新节奏一目了然。点较密时只会缩小标记，不会隐藏。
- **时间轴固定窗口**：横轴始终覆盖所选时间范围，历史数据只占据实际覆盖的时段，不会被拉伸铺满整个图表宽度。若开始记录的时间晚于范围起点，弹窗会提示第一条快照的时间。
- **刷新失败标红**：无法获取用量时，本次刷新仍会记录为失败数据点，并在图表上以红色标记展示。失败点会沿用最近一次成功快照的数值，因此刷新失败不会被误判为流量归零。
- **可自定义保留时长**：历史数据默认保留 180 天，可在「应用设置 → 用量历史」中修改，范围为 1 - 3650 天。调小保留天数会立即删除更早的快照。
- **按刷新绘制**：默认每条快照都会绘制成一个数据点，曲线与真实刷新时间一致，而不是被归并到整点。历史过于密集时会自动均匀降采样到最多 3000 个点（始终保留最新的点），迷你图最多保留 60 个点。
- **单点采样**：当前范围内只有一条采样时，图表会将其标记为圆点，并提示当前范围内只有一条采样。
- **仅机场维度**：用量数据来自机场的 `Subscription-Userinfo`，因此历史数据归属于机场。由于机场会被多个订阅复用，不再提供单独的订阅维度图表。

记录规则：

- 每次刷新尝试（无论成功或失败）都会写入一条快照，即使数值与上一条完全相同，因此每个请求都会在图表上留下一个点。
- 刷新失败会写入一个携带上次数值的失败标记，因此刷新失败不会被误判为流量归零。
- 系统每小时自动清理超过保留期的快照。
- 若刷新间隔为 30 分钟，每个机场每天约产生 48 条快照；刷新非常频繁时可适当缩短保留天数。
